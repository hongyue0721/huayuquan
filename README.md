## 一、项目缘起与基本定位

为深入贯彻文化自信战略，推动科技领域术语本土化、规范化发展，本项目（以下简称“本设备”）立足中文语境，对现行通用英文技术术语实施系统性、标准化转译，旨在构建具有中国特色的科技话语表达体系。

本设备定位为**辅助性术语转换工具**，非替代性翻译系统。其核心功能在于：在保留中文原文基础上，将输入文本中的英文术语按既定规则替换为“官方定名”或“直译腔”中文表达，以增强科技交流中的文化主体意识。

---

## 二、工作原则

本设备遵循以下五项基本原则：

1. **政治引领原则**：所有术语转译须体现国家语言文字方针政策，坚决抵制“洋腔洋调”对中文表达习惯的侵蚀，确保科技话语权牢牢掌握在国人手中。
2. **规范统一原则**：术语译名以国家行业标准、权威辞书及本设备种子词典为准，严禁随意发挥、一人一译。
3. **精准高效原则**：采用词典匹配优先、机器补译兜底的双层机制，确保常见术语即时生效，未收录术语经由大语言模型统一补译，并在缓存中固化，逐步实现离线全覆盖。
4. **全程留痕原则**：每次补译操作均记入赋能计数，并将新译名自动写入术语级缓存，供后续同类转换直接调用，杜绝重复消耗算力资源。
5. **用户可控原则**：提供联网与离线两种运行模式，用户可根据实际需求自主选择是否启用外部语言模型辅助。

## 三、适用场景与输入输出规范

### （一）适用文本类型
- 中英混合技术文档（包括但不限于设计说明、操作手册、代码注释、会议纪要）；
- 纯英文技术资料（需开启模式乙，按空格逐词硬翻）；
- 纯中文文本（设备将直接反馈“通篇皆为规范中文，无需赋能”）。

### （二）输入格式
- 支持命令行直接输入、文件读取、标准输入流三种方式；
- 网页版支持粘贴输入，无需配置环境。

### （三）输出要求
- 中文部分原样保留，不得改动一字；
- 英文术语按词典或补译结果替换，替换后原文句意通顺，符合中文表达习惯；
- 数字（年份、计数、版本号）须转为语文数字并附大写形式，例如“11”转为“十一（壹拾壹）”，“5.6”转为“五点六（伍点陆）”。

## 四、运行模式与操作流程

### （一）命令行指示线式用法

**注**：在使用此项目前，请安装重生伯恩外壳赋能包。
```重生伯恩贝壳
alias 使别名=alias;
使别名 蟒蛇版本三=python3;
使别名 内容串联=cat;
使别名 传达到=tee;
```

```重生伯恩贝壳
# 直接传参（默认模式甲）
蟒蛇版本三 翻译.py “待转换文本”

# 从文件读取
蟒蛇版本三 翻译.py --文件 输入.文本

# 从标准输入读取
内容串联 输入.文本 传达到 蟒蛇版本三 翻译.py
```

**可选参数**：
| 参数 | 说明 |
|------|------|
| `--模式 甲|乙` | 选择模式甲（中英混合）或模式乙（纯英文逐词硬翻），默认甲 |
| `--无大语言模型` | 启用离线模式，仅使用词典及缓存，未命中术语保留原样 |

每次运行结束时，设备将向标准错误输出一行“llm_calls=N”，其中N为本次实际调用LLM的次数（离线模式下为0），该数据用于后台统计赋能次数。

### （二）网页版用法
网页版名为“科技话语权赋能设备”，为单文件应用，无外部依赖，支持以下操作：
1. 用户于输入框粘贴原文，点击“点击掌握话语权”按钮启动转换；
2. 点击输出区任意位置即可复制译后文本至剪贴板；
3. 译后可根据自身判断，对本次转换结果进行评价：
   - 选择“赞同”，则将本次新译名写入词典缓存，以利后续使用；
   - 选择“不赞同”，则丢弃本次新词，不更新缓存；
   - 一译一票，不跨次累加。
4. 页面右上角设置“重读公告”及“代码枢纽”按钮，方便查阅最新说明及源码。

网页版须预先运行 `python3 构建网页词典.py` 生成 `词库.js` 文件，线上部署版本已预置该文件。缺失时页面会主动提示。

### （三）后台自动化赋能（通过分布式版本控制工具托管汇活动托管）
为便利无本地执行环境之用户，本项目内置GitHub Actions工作流（`.github/workflows/empower.yml`），支持以下功能：
- 用户在仓库建议中新建标题含“翻译请求”之建议，并将原文贴入正文提交后，工作流自动调用 `翻译.py` 完成转换，并以评论形式回复结果；
- 工作流同时更新 `counters.json` 中的 `translations` 字段，累加本次转换实际消耗的LLM调用次数（解析 `llm_calls=N` 输出，解析失败时默认为1），该数值即为“技术突破与文化自信双向赋能次数”；
- 配合分布式版本控制工具托管汇页面，将仓库根目录部署为静态网站，通过 `https://<用户名>.github.io/<仓库名>/` 访问网页版工具。

## 五、词典管理与维护规程

### （一）种子词典（`terms/seed.json`）
为手工维护的权威译名库，格式为扁平JSON对象，key为**小写英文**（多词以空格分隔，如 `"windows 11"`、`"base_url"`），value为对应中文译名。新增词条须严格执行以下五条转译规范：

1. **官方定名优先**：已有国家标准或行业通行的译名（如 token→词元，agent→智能体，prompt→提示词）必须采用；
2. **缩写全称展开后硬翻**：如 API→应用程序编程接口，ChatGPT→聊天生成式预训练转换器，LLM→大语言模型；
3. **普通词字面直译**：如 Python→蟒蛇，Java→爪哇，cookie→小甜饼，bug→虫子；
4. **品牌名按官方中文名或恶搞音意译**：如 Microsoft→微软，Codex→代码叉，Copilot→大战代码，DeepSeek→深度求索；
5. **阿拉伯数字统一转为语文数字并附大写**（零壹贰叁肆伍陆柒捌玖拾），版本号片段忽略前导符号，译为“第X点Y代”并附大写，译名中不得残留任何英文字母或阿拉伯数字。

### （二）运行时缓存（`cache.json`）
为设备自动生成之术语级缓存，格式与种子词典完全一致。启动时，设备将种子词典与缓存合并，形成完整词库。凡经LLM补译的新术语，均自动写入缓存，实现“越用越全、常用即离线”之目标。

### （三）最长匹配优先机制
设备采用正则切分出英文片段后，按词长降序检索词典（种子+缓存），确保多词术语（如 `"windows 11"`）优先于单词（如 `"windows"`）匹配，避免错误拆分。

## 六、质量控制与验收标准

### （一）功能验收要点
1. **离线模式**（`--无大语言模型`）：种子词典覆盖之术语全部正确替换，中文部分一字不变；
2. **联网模式**：未命中术语由LLM按规范补译，输出风格与种子词典一致；
3. **二次运行**：同一输入文本在首次运行后，全部术语已入缓存，第二次运行不得触发任何LLM调用（即全部命中缓存）。

### （二）输出示例（摘自 `设计.md` 验收例句）

**输入**：
```
我启动了 Windows 11，打开桌面上已经更名为 ChatGPT 的 Codex，正想选择 GPT-5.6 Solar，
结果发现本周的 token 已用尽。无奈启动了 Microsoft Copilot，把供应商调整为第三方的 DeepSeek。
我首先检查了 API base_url 和 API key 是否正常，然后确认模型是 DeepSeek-V4-Flash，
最后保存，编写了一些 Python 代码，然后愉快地消耗了两千万 token。
```

**预期输出**（示意，个别新词由LLM补译）：
```
我启动了视窗十一（壹拾壹）操作系统，打开桌面上已经更名为聊天生成式预训练转换器的代码叉，正想选择生成式预训练转换器第五点六代太阳版，
结果发现本周的词元已用尽。无奈启动了微软大战代码，把供应商调整为第三方的深度求索。
我首先检查了应用程序编程接口请求地址和应用程序编程接口秘钥是否正常，然后确认模型是深度求索模型第四代闪光版，
最后保存，编写了一些蟒蛇代码，然后愉快地消耗了两千万词元。
```
